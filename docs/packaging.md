# Packaging findings and release checks

## Host investigation

The investigated device reports SteamOS 0.5.2, variant `vr`, on Linux kernel `6.18.0-gaf9d0a0c005b`. Flatpak is version 1.15.8. A Flathub remote is configured and Freedesktop Platform 25.08 is installed; `flatpak-builder` was unavailable in the investigated environment. Discover consumes Flatpak and AppStream metadata rather than using a unique package format. These are environment findings, not a claim that an application package has been built, installed, accepted by Discover, or published.

The renderer uses GTK's OpenGL area with a Cairo fallback, rather than GStreamer `ximagesink`. The Flatpak manifest currently enables X11, PulseAudio protocol, and `--device=all` so that the tested desktop and V4L2 video devices can be exposed; Wayland is not enabled or validated here. `--device=all` is a broad device permission and must be reviewed against the target sandbox policy. Neither these permissions nor an installed runtime prove that a real capture card, host audio output, GTK rendering, or Steam Frame integration works in Flatpak. Validate on the real target hardware before release. The runtime's needed GStreamer elements/plugins must also be present and usable.

The SteamOS rootless archive bundles `libgstvideo4linux2.so`, `libgstjpeg.so`, and `libgstpulseaudio.so` from `gst-plugins-good` in `app/lib/captureviewer/gstreamer-1.0`, providing `v4l2src`, `jpegdec`, and PulseAudio device/audio support without installing the package on the host. This is not a fully self-contained GStreamer runtime: SteamOS still supplies GStreamer core/base, GTK, the plugins' shared-library dependencies, and kernel V4L2 support.

The recommended SteamOS distribution is the rootless AArch64 user-app archive captureviewer-steamos-aarch64.tar.zst, published with install-user.sh, uninstall-user.sh, bootstrap-support.sh, and SHA256SUMS. The workflow publishes these assets only after the changes are pushed and a matching v<version> tag is pushed; they are not published from this checkout yet. The app installs at ${XDG_DATA_HOME:-$HOME/.local/share}/captureviewer/app, while its desktop entry, icon, and AppStream metadata go into the user's XDG data directories. Re-running the installer updates the app. Ordinary app install/update/uninstall uses no pacman and writes no /usr. The conventional captureviewer-<version>-1-aarch64.pkg.tar.zst remains an optional Arch/developer artifact that writes under /usr, not the recommended Steam Frame path. SHA256SUMS is published beside the assets: it can detect changed/corrupt bytes against that list, but is not a detached signature or source/build provenance attestation and does not prove the archive came from reviewed source. Review release/tag and source independently.

The optional UVC support builder runs as the logged-in user. It may query pacman for kernel metadata, download the exact-version headers package and verify its archive against pacman’s repository SHA-256 checksum, and build for the running kernel; it never installs packages or writes under /usr. Builds use the upstream Linux base release corresponding to uname -r, not a claim of Valve’s exact patched kernel source; downloaded source files are checked against upstream Git blob IDs and recorded hashes, which are integrity checks rather than signed source provenance. Installing/updating the rootless app requires no separate manual bootstrap step: when startup detects an enumerated USB UVC interface that needs support and the trusted helper is absent, its Install offer runs the packaged bootstrap automatically. Bootstrap performs one `pkexec /usr/bin/install` invocation to install only the reviewed/root-owned helper assets in `/srv/captureviewer/uvc-helper`; it does not build or load modules. The same Install action then continues with the user-side build and root-helper install/load. First-ever setup may involve two privileged actions; normal Polkit caching may help but is not guaranteed.

Native `uvcvideo` takes precedence. At startup, an enumerated USB UVC interface requiring support gets an **Install** offer if native support is unavailable. If the trusted helper is absent, clicking it triggers the bootstrap described above and automatically continues through the user-side build and helper-mediated installation/loading; there is no required manual bootstrap, typed `INSTALL` confirmation, app reopen, or later navigation to Install. If a verified bundle for the exact running kernel is installed but unloaded and a USB UVC interface enumerates, startup offers **Load**. Native or already-loaded support produces no prompt. When USB is absent or no USB UVC interface enumerates, the app reports a device/system issue instead of offering Install/Load. Install/Repair/Load operations validate exact running-kernel support; the helper stages a verified bundle under `/srv/captureviewer/uvc`, installs/enables `captureviewer-uvc.service` under `/etc/systemd/system`, and insmods only verified modules without reboot. Kernel/vermagic mismatch fails closed. The support path never writes `/usr/lib/modules`, force-loads modules, changes SteamOS read-only mode, or installs packages with pacman. The boot service only verifies/loads root-owned support for the exact running kernel; it performs no network access or build.
Support-operation failures are surfaced in the GTK result dialog with the last error line, process status, and absolute setup-log path; the default is `${XDG_CACHE_HOME:-$HOME/.cache}/captureviewer/uvc-setup.log`. Validate both a logged build error and a missing-log/authorization-cancel path. The setup log records sanitized download URLs; SteamOS mirror tokens and non-`ref` query values are redacted.
